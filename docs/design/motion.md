## 0. 管线定性:程序化动效四件套(+美术帧动画合流)

全项目动效 100% 代码驱动,**零 AnimationPlayer、零 .tres 动画资源、零 shader**:

| 手件 | 用途 | 本项目约定 |
|---|---|---|
| `create_tween()` | 一次性 / 动态动画(出入场 / 演出) | 唯一 Tween 来源;缓动只在 M1 白名单;链式 `tween_interval` 做节奏 |
| `_draw()` + `queue_redraw()` | 逐帧程序化绘制(残影 / 滚动 / 刻度) | 有逐帧视觉的实体每帧重绘;禁止慢速像素位移(亚像素取整跳步,文字一律透明度过渡) |
| `CPUParticles2D` | 爆发粒子(置换 / 落尘 / 死亡碎片) | 见 §5 性能预算;移动端选型依据见 §5 |
| `Sfx.play()` 打点 | M6:landing 配音,无声动效 ≤0.4s | 音效引擎程序化合成(sfx.gd),与动效同 commit 调 |

**例外(历史)**:v0.12 曾规划美术帧动画管线(aseprite 雪碧图),
art-style.md §6.4)= 源图存首末态 + 中间帧,引擎侧 `Sprite2D` 逐帧播放——
这是"美术帧动画"接入"程序化管线"的唯一通道,新动画源先过 art-style §6。

选型依据(Godot 社区共识):Tween 管一次性 / 动态,AnimationPlayer 管
预制多轨预览——本项目"程序化优先"把前者推到极致;
AnimationPlayer 仅在"需要多轨编排"出现时立项
(现状:无此需求,单场景架构 + 截图钩子验收已覆盖)。

   `fade_to_black(dur, on_done)` 回调后再装载——**不引入 autoload
   TransitionManager**(单场景架构,Main 即根;社区常见的 autoload 方案
   在本架构里由 Hud 承担)。
2. **转场时长档**(M2 场景转场 0.5–0.8s 的落位):重开 0.25s(快,失败重试
   不拖沓)/ 换关 0.5s / 回菜单 0.5s;同屏只允许一个转场在飞
   (`_complete_seq` 序列号已防重入)。
3. **构成主义转场(v0.37 首批实装)**:纯黑渐变保持为"中性默认"
   (重开快档 0.25s 保留);三类**大流转**落地其二——肉鸽片段节奏
   (红色刻度块阶跃溶解,`BLOCKS_RED`)/ 换关(斜向扫掠 45° 红缘,
   `SWEEP`)/ 进关卡(取景框四角收拢揭开,`CORNERS`);宿主 = Hud 内
   TransitionFX 层(不引入 autoload,§2.1 裁定不变),同屏单飞,
   shader 两枚按 fx-light 卷三准入登记。幕间折线幕帘仍为规划。
   验收:`--transitionshot` 分镜 + `tests/transition_check.gd` 断言
   (四式 covered 恰一次 / 单飞 / 减动效硬切 / shader 可实例化)。

## 4. 性能预算(移动端优先)

- **粒子**:全用 `CPUParticles2D`(移动 GPU 驱动兼容性优于 GPUParticles;
  官方定位:小粒子量 CPUParticles 够用且更稳)。单次爆发 ≤24 颗,
  全屏同存 ≤200 颗;常驻粒子仅背景方尘(22+12)。**立项 GPUParticles 的
  唯一理由**:单效果需要 >500 颗(现状无;CPUParticles 自 4.2 功能冻结,
  大量需求出现时再评估迁移,注意 GPU/CPU 行为差异非 1:1)。
- **逐帧重绘**:每帧 `queue_redraw` 的实体 = 玩家(≤4)+ 门 + 构件 + 标注,
  巨构关(96×32 格)同屏可视实体受相机视野自然裁剪;新增常驻重绘实体
  先在此登记。
- **Tween 并发**:同节点串行(kill 旧的再建新的,如 narration/卡片),
  跨节点并发无预算上限但禁止每帧新建常驻 Tween。
- **帧率独立**(M9):全部用秒;常驻脉冲用 `Time.get_ticks_msec()`。
- 验收:巨构关 + 全演出齐发(置换爆发 + 残影 + 微震 + 方尘)在目标机
  稳 60fps(`--tourshot` 巡航截图逐点验)。
