# 音频设计 · AUDIO

> 状态:现行(v0.12 实装 · 2026-09-09 七音符体系与钢琴地板规划定稿)
> 现状权威:`scripts/fx/sfx.gd`(合成引擎 / 音效库)+ `scripts/fx/ambience.gd`(垫乐),
> 实现约定见 `docs/ARCHITECTURE.md`「音频架构」;本文是**设计权威**——
> 音高体系、音效与 BGM 的音乐规范、钢琴地板构件、与各系统的配合与后续兼容。
> 一句话:**全游戏同处 C 大调**——音效、BGM、玩家踩出来的旋律永不打架;
> 基建 = 零音频文件,一切程序化合成(纪律不变)。

## 0. 音频哲学

1. **零音频文件**:全部 22050Hz/16bit 一次性烘焙(AudioStreamWAV)或实时生成
   (Ambience);新音效 = 追加层规格,不引入 .wav/.ogg。
2. **统一音高体系**:关键音效主音、BGM、钢琴地板音符全部取自
   **C 大调自然音级**(do re mi fa sol la si);噪声层不受限(无音高)。
   已有实践升格为规范——`complete`(C5-E5-G5-C6 琶音)/ `fanfare`
   (G4-C5-E5-G5)/ `buff`(G4-C5-E5)早已在调内,审计见 §2。
3. **音色分工**(8-bit 芯片味不变):方波 = 旋律与琶音主角 / 三角波 = 铺底
   与柔和音 / 正弦 = 纯净音符 / 锯齿+噪声 = 打击与轰鸣。
4. **玩法音有 jitter(±3–8%),音符零 jitter**——随机音高是"生命感",
   对钢琴砖是"走音";`play_note` 路径强制 pitch_scale = 1.0。

## 1. 七音符体系(NOTE SYSTEM)

**基准**:十二平均律,A4 = 440 Hz;半音比 2^(1/12),八度 ×2。
**C 大调自然音级**(七音,C4 起表;同名扩展到 C2–C6):

| 音级 | C(do) | D(re) | E(mi) | F(fa) | G(sol) | A(la) | B(si) |
|---|---|---|---|---|---|---|---|
| 4 八度 | 261.63 | 293.66 | 329.63 | 349.23 | 392.00 | 440.00 | 493.88 |
| 5 八度 | 523.25 | 587.33 | 659.26 | 698.46 | 784.00 | 880.00 | 987.77 |
| 3 八度 | 130.81 | 146.83 | 164.81 | 174.61 | 196.00 | 220.00 | 246.94 |

- **Sfx.note 扩展**(规划 API,零破坏):
  - `NOTE` 静态频率表(音名 → Hz,C2–C6);
  - 层规格新增 `"note": "G4"` 字段,优先于 `f0`(`"f1"` 可留 Hz 做滑音);
    **现有音效不动**,新音效一律用 note;
  - `play_note(name, dur档)` ——钢琴音色 = tri 基频 + 泛音 [[2,0.3],[3,0.12]],
    两档包络:短 0.4s(踩踏)/ 长 1.2s(延音砖);
  - `play_chord(["C4","E4","G4"])` ——和音(踩头合奏 / 终点门封印);
  - 预烘焙 7 音 × 2 档 = 14 条流 + 池化播放器,运行时零合成(§6 性能)。
- **调式纪律**:主调 C 大调;抒情段允许关系小调 Am(A-C-E)——
  Ambience 现有 drone(A2/E3/A3/E4)即 Am 五度堆叠,天然合规。

## 2. 现有音效音高审计与迁移映射

| 音效 | 现状 | 判定 / 迁移方向(以耳朵终审,数值微调不改结构) |
|---|---|---|
| complete | C5-E5-G5-C6 琶音 | ✓ 已合规,登记为**过关 motif** |
| fanfare | G4-C5-E5-G5 铺开 | ✓ 已合规 |
| buff | G4-C5-E5 + E6 上滑 | ✓ 已合规(强化 = 上行三度跳进) |
| arrive | E5-A5-A6 | ✓ 调内(Am 色彩) |
| swap | 560→250 / 1120→500 | 迁 G4→C4 / G5→C5(下落感保留) |
| jump | 320→640 上滑 | 迁 C4→C5(上滑八度,速度感不变) |
| jump2 | 460→900 | 迁 E4→E5(二段跳 = 三度更高) |
| bounce | 300→96 | 迁 G3→C3(弹性落地) |
| land | 噪声 + 140→78 | 噪声保留;正弦迁 C3→C2 沉底 |
| switch / climb / ui_* / start / restart | 短促音 | 逐一吸附最近音级(±3% 内听感无差) |
| die | 240→52 锯齿下坠 | 迁 G3→C2(坠入低音区),噪声保留 |

- **音级语义化**(映射背后的规则,新音效必守):上行 = 获得/强化(jump/buff/
  complete),下行 = 失去/坠落(die/bounce/restart),同音重复 = 持续状态
  (climb),三度跳进 = 二段/强化,五度 = 确认/开启(ui_open = C4→G4)。

## 3. BGM:七音符序列器(Ambience 升级规划)

- 现状:`AudioStreamGenerator` 实时推送 Am 五度 drone(呼吸 LFO),无旋律无节奏。
- 升级:**节拍时钟 + 音序 pattern**——
  - 节拍时钟(BPM 60–90)`Sfx.beat_ticks` 公开,**动态构件可订阅**
    (TimedBridge 实心窗对齐小节,§5);
  - 每章一条 motif(4–8 小节循环,C 大调 / Am 交替):序章 = C 分解和弦
    铺底;第一幕 = Am→C 往复(引力排练的"起与落");肉鸽 = 按主角变奏
    (疾 = 快 BPM 方波短句 / 跃 = 三角长音 / 逆 = 低高八度对答 / 圆 = 连绵
    五度循环)——motif 即角色音乐画像;
  - 低音 drone 保留(层叠在 pattern 下),鼓 = 噪声层(调性无关)。
- 音量分治:BGM 走独立音量(设置面板第二滑杆,依赖音频总线,ROADMAP §5)。

## 4. 钢琴地板 PianoTile(structures.md §5 同步立项)

**概念**:踩踏 / 滚过即发声的平台砖——**玩家行为即配乐**
(业界参照 Sound Shapes:收集音符即演奏出原声)。依赖 §1 note API。

- **组件语义**:全套四元组(lane / faces / who)+ `note` 音级属性;
  **天花钢琴砖 = faces=bottom**(逆的对答高音区)——图层系统的音乐化收益。
- **空间映射规则(默认)**:音级 = 格坐标 y 反向映射(**越高 = 越高的音**,
  地图即乐谱);编辑器可逐砖覆写并做音阶吸附(白键限定,弹不出错音)。
- **角色 = 演奏手法**(角色动词的音乐翻译,新角色立项时同步登记):

| 角色 | 演奏手法 |
|---|---|
| 圆 | 滚过一排砖 = 连续**琶音 glissando**(速度越快音越密) |
| 疾 | 冲刺 + 跳 = **切分跳音**(只触落点几块,节奏感) |
| 跃 | 高反弹 = **同音重复 tremolo**(弹性 2.0 = 天然颤音) |
| 逆 | 地板砖 ↔ 天花砖置换 = **高低音区对答**(低音问、高音答) |
| 踩头 | 双人同砖 = `play_chord` **和音** |

- **触发规范**:落地速度 → 音量(重落地响);触发冷却 0.15s 防连发
  (glissando 圆例外:冷却减半保持音流);触发演出 = 砖顶缘亮线脉冲
  (M5 量级)+ 音符粒子(引用 motion.md §1 爆发规格,颜色 = 音级色相
  在 PAPER/RED 纪律内的微差)。
- **与 BGM 同调保证**:本关 BGM 调式 = 砖音域同调(C 大调内任意组合皆和谐)
  ——玩家即兴永远"在调内",这是锁 C 大调的玩法理由。

## 5. 与各系统配合矩阵

| 系统 | 配合点 |
|---|---|
| **图层系统**(levels.md §7) | 钢琴砖是全语义组件;天花砖 = 逆的对答区;who 专属砖 = 角色专属乐器 |
| **动态构件**(structures.md §5) | TimedBridge / LeverGate 可订阅节拍时钟——**机关踩在拍点上**,可预读性升级为可"听"预读 |
| **肉鸽**(roguelike.md) | 词条规划:「绝对音感」(踩砖连击 → 回一段红色刻度 / 速度小 buff)、旋律关选路卡(风险 = 节奏平台更快) |
| **编辑器**(editor.md) | 钢琴砖组件 schema(note 属性 + 音阶吸附 + 点击试听);验证器警告"调外音级";分享码 JSON 增 note 字段(旧关缺省 = 无砖,向后兼容) |
| **UI / 设置** | 音频总线拆分后 BGM 独立滑杆;钢琴砖音量随 SFX 总线 |
| **叙事 / 剧情音** | story_next 等剧情音入调;大风琴关 = 钢琴砖的"管风琴"变奏(长音档) |

## 6. 性能与后续兼容

- **运行时零合成**:音符流预烘焙(14 条)+ 池化播放器(≤8 并发,
  glissando 峰值够用);烘焙发生在 `Sfx.init()`,首帧前完成。
- **音频总线**(ROADMAP §5 既有项):SFX / Music / Master 三总线落地时,
  play_note 走 SFX,序列器走 Music——拆分前后 API 不变。
- **新角色 / 新关**:演奏手法与 motif 是角色 / 章节立项清单项
  (characters.md §10 矩阵已挂「音乐」行);新关可不设砖(钢琴砖是可选语义,
  不是全局依赖)。
- **分享码 / 存档**:砖的 note 字段进 LevelDef 同构 JSON,校验器拒绝
  调外音级;旧格式关卡无字段照常装载。
- **验收**:音符 API 落地后 `--autotest` 附带静音断言(音效注册数 /
  音符流数);真机验证 glissando 并发不爆音(移动端 mixer 上限)。

## 7. 立项顺序

1. **七音符基建**(NOTE 表 + note 字段 + play_note/chord + 现有音效迁移)
   ——独立发版价值:全音效和声化;
2. **序列器 BGM**(节拍时钟 + 章节 motif)——依赖 1;
3. **钢琴砖构件 + 试水关**(一关置入钢琴地路段)——依赖 1,与 2 并行可;
4. 编辑器砖编辑 + 肉鸽词条——依赖 3。
