# 地图编辑器设计 · EDITOR

> 状态:定稿(2026-09-09 探讨定稿 · v0.13 立项;技术方案与里程碑见 `docs/ROADMAP.md` §1)
> 一句话:把关卡从"手写数据"升级为"组件拼装"——瓦片铺地形、组件摆建筑,
> **语义四元组(lane / faces / who)**决定谁能通行、谁遮谁,验证器守数值规范。
> 平台策略:**桌面键鼠优先**开发与测试;移动端触屏版后置,真机反复测试优化。

## 0. 设计目标与边界

- **目标**:玩家(以及我们自己的关卡组)在网格画布上用瓦片与组件拼装关卡,
  自定义画布、编辑功能建筑的属性、一键试玩、生成分享码。
- **一套数据两个用户**:编辑器产物 = `LevelDef` 同构 JSON,与手写关卡
  (`level_data.gd`)走**同一条 `LevelBuilder.build` 装配路径**,运行时零分支。
  官方关卡未来也迁到同一格式(编辑器成为内部关卡工具,不是外挂玩具)。
- **不是**:自由绘制画笔。所有可放置物都是**登记过的组件**
  (data 层 schema),画布上没有"野对象"——这是验证器能守规范的前提。

## 1. 双层内容模型

内容分两类,对应两种放置手感(业界成熟范式:瓦片管"面",对象管"点"):

| 层 | 内容 | 放置手感 | 碰撞来源 |
|---|---|---|---|
| **瓦片层**(地形) | tileset terrain 16 片 + 坡面 6 片(art-style.md §6.3) | 笔刷刷矩形面,四边暴露位自动选片(autotile) | 瓦片自身声明 faces(默认 full);**像素图不承担碰撞**,碰撞仍由组件属性驱动 |
| **组件层**(建筑) | 巨柱 / 电梯 / 加速门 / 曲面 / 终点门 / 出生点 / 教学牌 / 动态构件(§3) | 单件拖放,吸附 1 格;拖出属性面板 | 由各构件实体负责(与现行为一致) |

- 瓦片笔刷自带**语义默认值**(lane=mid / faces=full / who=全员),
  刷出来的地形自动拥有正确碰撞与层级。
- 组件层托盘按 `tileset` 图集五层分类一一对应
  (terrain / ramps / decor / mover / guides → 美术加一层分类,编辑器多一组笔刷)。

## 2. 组件 schema

每个组件类型一份 schema(纯 data 层定义),实例 = schema + 变换 + 属性覆盖。
schema 字段三类:

1. **变换**:位置(格)、尺寸(格;带默认与上下限,如电梯板 1×0.5 格)。
2. **语义四元组**(与 `levels.md` §7 共用一套定义,不重复建模):
   `lane ∈ back/mid/front`、`faces ∈ full/top/bottom/none`、
   `who`(适用几何体集合,空=全员)、`tags`。
   编辑器里做成**一键档位**而非裸字段:预设"主路面 / 背景结构 / 逆的天花板 /
   单向薄板 / 疾专属"等常用组合,高级面板再暴露原始四元组。
3. **功能属性**(按类型):

| 组件类型 | 可编辑属性 |
|---|---|
| 电梯 Mover | `offset`(行程向量,格)、`period`、`phase`;档位预设:慢速 3s / 中速 2s / Express 行程×1s |
| 加速门 SpeedGate | 倍率(默认 2.5)、朝向 |
| 曲面 Ramp | 折点序列(拖点编辑)、`base_y`;吸附规范:折角步进 ≤7° |
| 终点门 ExitDoor | 归属几何体(四色单选) |
| 出生点 Spawn | 归属几何体(分位出生配对校验,§5) |
| 教学牌 Hint | 文本(桌面键盘输入)、锚点 |
| 动态构件 | 见 §3 |

- 属性面板 = **schema 自动生成**(托盘同源),新增组件类型零 UI 改动。

## 3. 动态组件(首版即进 schema,进入测试)

运行时切换碰撞语义的构件,依赖图层系统的运行时位切换
(`set_collision_layer_value`,见 levels.md §7.6):

| 构件 | 机制 | schema 增量 |
|---|---|---|
| **开关门 LeverGate** | 场内踩踏开关( lever)与门板成对;踩下 ↔ 门板在 full/none 间切换 | `trigger`(开关位置)、`states`(两种状态的 faces)、切换演出(硬投影塌缩 / 直线弹出,M1 白名单) |
| **限时桥 TimedBridge** | 周期性实心 ↔ 虚化(虚化期无碰撞、降透明度至 §7.7 前景规则之下) | `on_time / off_time`(秒,各自 ≥1.0s 保证可读)、相位 |

- 设计纪律:**切换必须可预读**——门板在虚化态保留 8% 亮度线框(虚线段),
  桥保留轨道线;玩家看一眼就能算出"下一次实心是什么时候"。
  (动态地图原则 levels.md §3 的推广:动态的是状态,不是规则。)

## 4. 画布规范

- 画布大小以**格**定义(宽 × 高),`LevelDef.size` 直接推导;建图向导输入格数。
- 建议上限 **128 × 40 格**(现最大关 100 × 32;Mario Maker 以 257×28 上限
  约束创作质量的先例);超出可保存但验证器警告。
- 边界:画布边缘即相机四锁,越界不可放(与"相机四锁即世界"一致,levels.md §0);
  左右隐形墙由构建器自动补,不可编辑。
- `kill_y`:默认画布底缘 +2 格;可下拉(地面安全网关,levels.md §6.2)。

## 5. 验证器(编辑器的灵魂)

三件套,保存 / 试玩前自动跑,结果面板列出"错误(阻断分享)/ 警告":

1. **数值医生**:对照 `levels.md` 数值规范检查台阶与缺口——≤1.6 格(普通跳)
   / ≤2.6(二段跳)/ ≤3.5(冲刺二段跳)/ 更宽须有替代路;梯田步高、
   Express 档行程-周期关系等;违规处画布上红框标注。
2. **路径医生**:**可通关试探**——复用 `--autotest` 走跳 AI(ROADMAP §5 技术债:
   先抽成独立类)在后台跑"每位出生几何体 → 其归门",不通则报
   "疑似不可通关"(警告不阻断,人眼终审)。
3. **配对医生**:出生点 / 归门按几何体一一配对;roster 内每个几何体
   都有出生点与门;动态构件的开关与门板成对;`who` 专属组件
   必须有该几何体的通路(否则它只是装饰)。

## 6. 试玩一体化

- **放下即玩**(Mario Maker 的核心循环:放置 → 试玩 → 返回编辑):
  编辑器一键切换当前画布为试玩模式,`LevelBuilder.build` 直接吃画布数据,
  Esc / 手柄 Back 返回编辑器并保留未保存改动。
- 试玩起点:默认全部出生点;可选"单主角试跑"(只生成指定几何体,
  便于验证专属路线)。

## 7. 网格与量尺

- 编辑器网格与游戏内定位网格**同一把尺**(1 格 = 100 px;levels.md §8):
  吸附步长、瓦片对齐、HUD 读数、组件坐标全部同源,所见即所得。
- **量尺模式**:拖动组件时显示与邻近组件的格距读数,并按规范变色
  (合规 = 纸白 / 触线 = 黄 / 违规 = 红)——网格从背景升级为
  数值规范的可视化量尺。
- 层级面板:lane 三档分组显示(back 组降亮度预览),可单组隐藏 / 锁定;
  点选组件即跳属性面板。

## 8. 保存 / 分享 / 存档

- **文件格式**:`LevelDef` 同构 JSON(`Vector2` 存 `[x,y]` 数组),头部带
  `format_version / title / author / engine_version`;官方关与玩家关同构。
- **玩家关卡**存 `user://`(SaveManager 新区段,`SAVE_VERSION` MINOR+1 迁移)。
- **分享码**:JSON → DEFLATE 压缩 → Base64url(可进二维码 / 剪贴板);
  导入时校验版本与字段,拒绝越界数值。技术细节见 ROADMAP §1。

## 9. 界面布局(构成主义语言)

```
┌──────────────────────────────────────────────┐
│ 顶栏:文件 / 撤销重做 / 档位(lane 三键) / 试玩▶ │
├──────┬──────────────────────────────┬────────┤
│ 托盘 │                              │ 属性    │
│ 瓦片 │        画布(网格 + 量尺)      │ 面板    │
│ 组件 │                              │(schema  │
│ 动态 │                              │ 自动生成)│
├──────┴──────────────────────────────┴────────┤
│ 底栏:验证结果条(✓ 通过 / N 错 N 警) / 光标坐标 │
└──────────────────────────────────────────────┘
```

- 沿用 art-style.md 全部禁则:直角 / 硬投影 / 无圆角无渐变;
  强调色只用构成红(当前笔刷档、违规标注、试玩按钮)。
- 组件在画布上的**画布外观 = 游戏内渲染**(同一路径),含 lane 降亮度与
  faces 预览(top 薄板减薄显示、bottom 面加底缘蓝线)——编辑时看到的
  遮挡与层级就是游戏运行时的。

## 10. 平台策略:桌面先行,移动端后置(定稿)

- **首版 = 桌面键鼠**(Godot 内嵌工具场景,开发与测试全在桌面完成):
  拖放 / 框选 / 滚轮缩放 / 空格拖画布 / 快捷键(1-9 选笔刷、Ctrl+Z 撤销)。
- **移动端触屏版后置**:完整编辑器在触屏上体验难做好,不硬移植;
  待桌面版打磨完,再做**极简触屏画笔**(仅瓦片刷 + 组件摆放 + 属性滑杆,
  无框选无快捷键),并以真机反复测试优化交互(误触、掌托、性能)。
- 游戏内移动端入口只保留**「玩他人关卡」**(分享码导入 / 关卡列表);
  创作入口在桌面。
