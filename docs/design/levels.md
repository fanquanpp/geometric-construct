## 1. 关卡写作流程(从 TWA 学到的)

1. 先定教学段名(像 TWA 作者给段落命名 "Jump Up" / "Jump Gap with Rise"),
   写进 `intro` 字段:第一行教操作,第二行教原理。
2. 跳距公式化:满跳高度 h = v²/2g → 普通跳缺口 1.2–1.9 格,二段跳缺口 2.6 格,
   冲刺+二段跳 3.5+ 格;上升台阶 ≤1.9 格(2.0 格跳高 − 0.1 余量)。
3. **节奏三段式**:热身(安全,纯走)→ 教学点(安全网)→ 考验(失败惩罚轻,
   重生点近)→ 出口前缓冲(让玩家喘口气再看结算)。
4. 视线引导:用红色刻度块、门牌、曲面亮线把玩家视线"排"向前进方向;
   死路只用一次,且必须给视觉补偿(大号数字或装饰巨面)。

## 2. 现有关卡解析(v0.8 迭代后)

### 01 疾 · 跳跃(教学:跳跃 / 速度-跳远正比)
- 平面 + 三段渐宽断崖(1.2 / 1.9 / 2.6 格),末缺口必须二段跳(冲刺更稳)。
- 开局即 5.6 格长直道热身带,出口前有 2 格缓冲台;无运动构件(第一关保持静态)。

### 02 跃 · 攀高(教学:切换 / 踩头合作 / 二段跳)
- 台地 A(1.6 格)+ 高台 B(3.2 格);垫脚台 0.6 格供"跃上同伴头顶"教学。
- v0.8:高台 B 左缘新增**垂直移动平台**(振幅 2.4 格 / 周期 3.2s,可等待)——
  提供"不合作的慢路",踩头接力仍是快路(解法分层,难度可选)。

### 03 逆 · 突破(教学:置换 / 加速门)
- 上下双平台 + 0.6 格矮墙(不可跳,必须置换)+ 双侧断口;加速门后大弧线飞跃。
- v0.8:天花板断口内新增**水平接驳台**(行程 1.3 格 / 周期 2.8s)——
  置换失误不再直接坠亡,惩罚降级为"多等一个周期",教学关不劝退。

### 04 圆 · 过山车(教学:切线飞跃 / 极速)
- 两座曲面跳跃板 + 双断路(2.6 / 7.8 格);2.5× 飞跃 7.8 格。
- 本关刻意**不设运动构件**:速度考验路径里不放"可等待"要素,
  出手时机本身就是这关的时间维度(动态地图原则 §3.2 的反例保留)。
- v0.15:末缺口后新增**冲刺跳 showcase**(3.4 格缺口,冲刺 + 二段跳),
  给"速度 = 射程"一个纯速度解法的收束拍(§10.2)。

### 05 机关 · 合拍(v0.15 新增,教学:动态构件 / 合作分工)
- 序章第五场,跃 + 疾双人。三拍:**限时桥**(实心 ↔ 虚化 2s 周期,
  数拍通过;坠落 = 落回地面软惩罚)→ **开关门互让**(双人两道门 +
  两只踩踏开关:疾踩 A 门跃先过,跃踩 B 门接疾过来)→
  **接驳台终拍**(垂直移动平台等一班,登上终场高台双门归位)。
- 教学概念 = "可预读的状态切换"(structures.md §5 动态构件族):
  限时桥 / 开关门全部保留 8% 亮度线框 + 轨道线,虚化态可见、实心态可数。
- 全程地面安全网;两道门板从 y2.4 格直落到地面,跳不过去——
  合作是唯一解,呼应"互相借力"的序幕约定。

### 06 合演 · 四人同行(v0.15 新增,教学:切换自由 / 序章终场)
- 序章收官场,四人合演的微缩版(第一幕的分位归门前置预演):
  同一张地图上四条能力路线并置,全部出口门同屏可达。
- **圆线**:地面加速门 + 起飞坡,飞越 3.2 格 × 2.4 格的高墙窗;
- **疾 / 跃线**:高墙二段跳直翻,或东侧梯田逐级登高台(步高 ≤1.6 格);
- **逆线**:置换上中段梁底,沿梁底东行越过墙顶上空,再置换落地;
- 四门分位:疾东台 / 跃高台 / 逆悬梁底 / 圆墙东地面——
  开场教学牌点题:"轮流送每个人回家"。

## 3. 动态地图原则(v0.8 起,"地图也可以是动态的")

1. **运动构件只做两件事**:连接(transport)与 变奏(variation)。
   连接 = 移动平台补断路;变奏 = 让静态谜题多一个时间维度。
2. **教学关的运动必须可等待**:移动平台慢速(≥3s/程)且不会把玩家推向死区。
3. **背景是活的,前景是稳的**:视差层缓慢漂移 / 呼吸(增量 ≤10%),
   平台本体保持预测性(踩上去之前就能算出落点)。
4. TWA 式动态平台参数:相对路径点 + 缓动 + `pause` 停顿 + 循环;
   本作简化为单轴往返(offset 向量 + period + phase),够用且可 JSON 化。

## 4. 配色与章节化(借鉴 TWA:平台色由背景推导)

- 平台基色 `#262B34` / 亮面 `#313845` 保持全局统一(可读性优先);
  章节感交给**背景巨面**与**门牌 / 刻度**的角色色密度表达:
  疾关红刻度密,跃关黄点缀多,逆关蓝,圆关橙。
- 背景亮度红线:任何背景元素 ≤ PAPER·8% 亮度(见 art-style.md §4)。

## 5. 正式关卡:第一幕「引力排练」(v0.11 起 · v0.12 六场全演)

序章六场(v0.15 扩容:四场单演 + 机关合拍 + 合演终场)各教一个几何体
与合作语言;第一幕起才是"真正的剧演"——四人合演,
每场都是**大型多几何体关卡(巨构主义)**:尺度 3 倍于序章(长 ≥90 格 /
高 ≥25 格),单一结构里并置多条能力路线。六场全部开演:

| 场次 | 剧名 | 组合题 | 核心句 |
|---|---|---|---|
| 01 | 巨构门厅(v0.11) | 天路 × 地路 × 分位归门 | "每个人走自己的路,在各自的门里归位" |
| 02 | 承接天桥(v0.12) | 承载接力:跃为梯 × 疾为腿 | "最快的腿,踩在最稳的肩上" |
| 03 | 双面回廊(v0.12) | 置换交叉:天路地路互换 | "一廊两面,梁上梁下都是路" |
| 04 | 速度圣殿(v0.12) | 加速门竞速:圆 × 长断路连飞 | "速度即跳跃" |
| 05 | 碎裂穹顶(v0.12) | 动能谜题:曲面板阵 × 移动接驳 | "出手时机即一切" |
| 06 | 幕间 · 大风琴(v0.12) | 幕终全组合 | "四能力齐奏,幕落" |

**分位出生 / 分位归门**(01 场确立的趣味原则):四个几何体不再共享出生点
与一排终点门,而是各自从巨构的不同角落出发、在属于自己的位置归位——
逆的门可以悬在天梁底面,圆的门立在飞跃的尽头。角色差异即路线差异,
路线差异即游玩差异。

### 05 · 巨构门厅(v0.11 实装解析)

- 尺度 96 × 32 格;地面 y28 全程贯通 = 安全网(坠落即回到中庭,
  `kill_y` 下移至 3300,大落差无惩罚)。
- **天路**(疾 / 跃):西翼五级浮田(步高 1.4 格,首级 2.6 格需二段跳)→
  空中踏石(缺口 1.8–2.6 格)→ 巨柱交替横杆(步高 2.6 格)→ 柱顶 → 高架连桥。
- **地路**(圆;逆亦可):浮田下方 1.4 格净空隧道 → 地面加速门 →
  **曲面冲柱**:3°→37° 渐陡曲面把圆送进柱心中空(离地 2 格、净高 2.4 格的
  穿柱之路),穿柱落地后直奔巨构电梯(行程 19.6 格 / 周期 20s)→ 连桥。
- **天堑**(连桥 7.5 格断路):圆走加速门 2.5× + 曲面 1.5× 全速飞跃(04 场
  证明射程);疾走浮石(双跳 2.2 / 1.6 / 1.7 格);逆置换上天梁从梁底越障。
- **天顶巨梁**(50 格整根,x44–94):逆的天路,两端挡缘防置换行走坠出;
  逆的门悬于梁底(y5.46 格),从梁顶置换翻到梁底走入。
- 四门分位:疾塔顶 / 跃柱巅 / 逆梁底 / 圆桥尾。

### 06 · 承接天桥(v0.12 实装解析)

- 尺度 92 × 30 格;地面 y26 全程贯通 = 安全网。
- **承载题**:断桥缺口 3.6 格——超出冲刺二段跳的稳射程;跃先登西引台
  (步高 1.6 格)站上断缘当"活台阶",疾踩跃头顶起跳,借 1 格头高
  + 高落点跃过天堑;踩头失误落地面 = 重爬(安全网轻惩罚)。
- **跃线**:三级塔肩(步高 2.8 格 ×3,二段跳逐级),门立塔肩之巅。
- **逆线**:桥下出生,一次置换翻上天桥底面(净空 0.8 格),沿梁底东行,
  门悬桥底(y25.66 格)。
- **圆线**:出生即过地面加速门(2.5×),冲 18° 出口曲面落桥东段,
  门在桥东尽头;桥下慢电梯(1.6 格 / 3.2s)供坠桥者恢复。

### 07 · 双面回廊(v0.12 实装解析)

- 尺度 96 × 28 格;完整天花板(y8)是逆的天路,地面缺口 3.0 格(x24–27)
  逼逆置换上行;两端挡缘防坠出。
- **夹层中板**(y16,x34–70):疾 / 跃的第二面天路——西端三级台阶

- **圆线**:地面加速门 + 起飞坡飞越 3 格缺口;门在廊中凸台(0.4 格)。
- 门位:疾东端高台 / 跃更高浮台 / 逆悬天花板底 / 圆廊中凸台——
  一廊四面,各归各位。

### 08 · 速度圣殿(v0.12 实装解析)

- 尺度 96 × 30 格;地面安全网;主赛道 = 三段「加速门 → 曲面 → 大断路」:
  37° / 37° / 45° 出口(2.5× + 曲面 1.5× = 1125 px/s),射程与落台
  逐段校核(落台 A y23 / 落台 B y22 / 终殿台 y19),圆从地面连飞到终殿。
- **高架天路**(y14.4,x18–52):疾 / 跃走高架,三连浮石缺口 2.0 格 ×3,
  东段缺口由 45° 抛物顶点(净空 >1 格)从下方穿过——轨迹互不穿插。
- **逆线**:双段置换——地面 → 落台 A 底 → 高架底,门悬高架底(y16.06)。
- Express 终殿电梯(7 格 / 7s)贴终殿台,失败者绕回终点。

### 09 · 碎裂穹顶(v0.12 实装解析)

- 尺度 92 × 30 格;地面安全网;四块放射曲面(0°→40°→43°→50°)逐级弹射,
  曲面之间全靠**移动接驳**:垂直接驳(行程 3 格 / 3.2s,台位对准抛物线下落点)
  → 水平接驳(行程 2.4 格 / 2.8s)→ 50° 大抛跃上终穹台(顶点 y10.4)。

### 10 · 幕间 · 大风琴(v0.12 实装解析)

- 尺度 100 × 32 格;幕终巨构:一座管风琴,四根音管各考一种能力——
  管·疾 = 交替横杆井(步高 2.6 格 ×7)/ 管·跃 = 之字台阶井(1.6 格 ×10)/
  管·逆 = 置换井(井顶板 → 琴台底,双段置换)/ 管·圆 = 曲面冲天井

- Express 主电梯(20.2 格 / 20s)贴琴台东端 = 全员慢路;幕落即 WIN。

## 6. 巨构关卡规范(在 §0–§4 基础上的增量)

1. **尺度基准**:长 ≥90 格、结构高 ≥25 格;相机四锁仍即世界。
2. **安全网原则**:至少一条全程贯通的地面(或接驳网),`kill_y` 随之下移;
   巨构里"坠落"是绕路而不是死亡(失败惩罚 = 重爬,重生点近的自然等价物)。
3. **双线法则**:每段大结构至少两条能力路线——跳跃系快路 + 电梯 / 隧道
   慢路;慢路必须可等待、可恢复。
4. **巨构档构件**:教学关 mover 规范(§3)之外新增 Express 档——
   行程 10–20 格、周期 = 行程(格)×1s(峰值速度 ≈3.1 格/秒),
   只用于长距垂直连接,轨道线必须全程可见。
5. **门位叙事**:终点门位置讲角色的话(逆门悬空、圆门在速度尽头、
   跃门在最高处);门即奖赏风景位。

## 7. 组件语义与图层系统(v0.13 规划定稿 · 2026-09-09)

> 背景:当前全部平台在一个 StaticBody2D 里四面实心(`level_builder.gd`),
> 重叠组件互相封死——天梁穿过东塔处、琴台出音口、回廊天花板与登廊台阶
> 相交处,角色被"不该挡路的墙"挡住;逆的置换落点只按重力反向找面,
> 不感知哪面**应该**可站。本节定义"地图组件"的语义模型,是
> 运行时编译(ROADMAP §1 M0)的唯一依据。

### 7.1 三个"层"分开设计

| 层 | 问题 | 机制 |
|---|---|---|
| 物理层(谁碰谁) | 重叠组件封路 | `lane` 层级 + 碰撞位(§7.6) |
| 适用层(谁能用) | 路线归属不清 | `who` 集合 + `faces` 朝向(§7.3–7.4) |
| 渲染层(谁遮谁) | 前后景无语义 | 显示档五档 → z_index + 降亮度/渗雾规则(§7.7) |

### 7.2 组件语义组(v0.14 扩展:逐几何体层级 + 远景沉降)

地图组件(平台 / 瓦片地形 / 建筑构件)一律携带:

```
组件 = { 几何(位置/尺寸/折点), lane, faces, who, lanes, far, tags, … }
  lane  ∈ back | mid | front      # 原生层级:背景结构 / 主层 / 前景遮挡
  faces ∈ full | top | bottom | none
  who   = {疾,跃,逆,圆} 子集,空 = 全员
  lanes = {几何体: lane}          # 逐几何体层级归属(v0.14,§7.7)
  far   ∈ -1 | 0 | 1 | 2          # 不适用时的沉降档(v0.14,§7.7)
  tags  = ramp / mover / door / …  # 现有语义标签收编
```

- 一座建筑由此可以**同时归属多个图层等级**:对不同几何体处在不同层级
  (`lanes`),对不适用者沉降为远景(`far`)——层级随受控几何体切换而升降,
  碰撞仍只由 `who` 决定(`lanes` / `far` 不进碰撞组合键)。
- 缺省 `lanes={}` / `far=-1` 时行为 = v0.13 四元组(数据零迁移)。

> v0.18 拍板(§7.10):`lanes` / `far` 将废弃——一组件一层,
> 分层差异拆两个组件表达;`lane` 升格为八层定值 `layer`(1–8)。

### 7.3 faces 四档(定稿:首版不做"仅侧壁实心")

| faces | 语义 | 典型用途 |
|---|---|---|
| `full` | 四面实心(现状) | 主路面、巨构实体 |
| `top` | 仅顶面实心 = 单向薄板,可自下方穿过、上方可站 | 夹层中板、天桥桥面(防下落误撞) |
| `bottom` | 仅底面实心(顶面可穿) | **逆的天花板面**——置换目标专用 |
| `none` | 无碰撞纯装饰 | 背景巨面、出音口装饰 |

- 不做"仅侧壁实心":现有关卡里侧壁场景(挡缘、井壁、爬墙横杆)全部是
  完整矩形,无实装需求;真出现时再扩档,schema 不预留。

### 7.4 who:适用几何体(定稿:整体不碰撞)

- `who` 不含某几何体 = **该组件对此几何体完全不存在**:
  不能站、不能撞、**也不能爬**。
- 决策理由:① 语义单一,"视觉即机制"——不适用组件在对应几何体的
  视野里**沉入远景层次**(§7.7,v0.14 起为两档冷色远景;`far:0` 可保留
  v0.13 的原位降透明),玩家一眼读懂"这跟我无关";
  ② "可站不可爬"是反直觉组合(站在墙上却爬不上去),禁止;
  ③ 疾的爬墙是核心机动,`who` 过滤它会让专属路线更清晰。
- 后续真有"可站不可爬"需求,再加独立 `climb` 开关字段,不动 `who` 语义。

### 7.5 置换(逆)的目标面规则

`_perform_swap` 的落点查询加语义过滤:**当前 lane 内、
`faces ∈ {full, bottom}` 且 `who` 含逆**的组件,按重力反向取最近可站面。
"置换落到被重叠结构堵死的位置"从机制上消除。

### 7.6 编译与渲染(实现概览;技术细节见 ROADMAP §1 M0)

- **碰撞位编译**:构建期把 (lane, who) 实际出现的组合分配 Godot 碰撞位
  (32 位预算,常用组合 < 10);玩家 `collision_mask` = 其适用组合位并集,
  **出生时算定一次,运行时零开销**。动态构件(§7.8 / structures.md §5)
  运行时 `set_collision_layer_value` 切换。
- **渲染映射**(v0.14 五档):显示档 → z_index
  (far2=-2 / far1=-1 / back=0 / mid=1 / front=2),远景两档沉到定位网格
  之下;`_rests_on` 投影裙角逻辑只认**同档且可见**的承接块(承接块沉入
  远景后,立块投影自动还原为落地态)。渲染唯一管线为
  LayerVisual 节点分层(v0.39.0,引擎内置 Polygon2D/Line2D)。
- **兼容性**:默认值 `lane=mid / faces=full / who=全员 / lanes={} / far=-1`
  与现状行为一致,序章 + 第一幕 10 关**零迁移**(官方关尚无 `who` 数据,
  自动沉降暂只在图层实验室生效)。

### 7.7 逐几何体层级归属与远景沉降(v0.14 迭代定稿)

一座建筑不再是"一个 lane 定死",而是**对每个几何体各有一个归属层级**;
对当前受控几何体不适用的建筑则整体沉入远景,形成多层纵深。

- **逐几何体层级 `lanes: {几何体: lane}`**:同一建筑对不同几何体可以
  处在不同层级(如对疾是主层 mid、对跃是背景 back,二者都可站立);
  缺省回落 `lane`。层级只影响渲染(z / 亮度),碰撞仍由 `who` 决定。
- **远景沉降 `far`**:对受控几何体不适用的可碰撞建筑,不再原地淡化,
  而是**沉入网格之下的远景两档**:

  | 显示档 | z | 视觉 | 规则 |
  |---|---|---|---|
  | far2 最远 | -2 | 渗雾 74%,仅余轮廓 | `far:2`,或自动分档距受控体 > 7 格 |
  | far1 远 | -1 | 渗雾 66%,冷色幽灵板 | `far:1`,或自动分档距受控体 ≤ 7 格 |
  | hold 原位 | 不变 | 原位降至 30% | `far:0` 显式保留 v0.13 行为 |

  `far` 缺省(-1)= 自动按与受控几何体的距离分档(切换时刻计算一次,
  不逐帧抖动)。
- **切换几何体**:原远景建筑回升到归属层级、新不适用者沉降 —— 按距离
  **波次级联**(近处先动,≤ 0.3s),档间转移走交叉淡化(旧档淡出、
  新档淡入,z 切换藏在透明谷里,无跳层 pop)。
- 视觉纵深梯度:mid / front 实色 → back 压亮度(背景红线内)→
  far1 冷色幽灵 → far2 轮廓,共四步;全部由引擎 modulate / alpha 实现,
  **不重画瓦片**(art-style.md §6)。
- front 遮挡与 back 压亮度规则不变:front 层组件在玩家躲入其后时降至
  ≈55% 透明度保证角色可见;back 层亮度压到背景红线内(art-style.md §4.1)。

## 7.9 分层语义 v2(v0.17 实装:"视觉分层 = 碰撞分层")

- **lane 升级为碰撞域**:组件对几何体 g 有碰撞,当且仅当
  `applies_to(g)` 且 `lane_for(g) == mid`;back / far1 / far2 / front
  全部纯视觉,几何体可自由穿行——所见即所碰,几何体不再被
  其他层建筑物体积挡住(v0.16 真机实测反馈,最严重项)。
- front 层 z 提升到玩家之上(6 > 5):纯遮挡层,躲入其后降 55% 呈剪影。
- 碰撞位编译改为"实体签名":组件按"适用且对自己是 mid"的几何体集合
  分组共享碰撞位;动态构件(限时桥 / 开关门板)逐实例独占位,
  防运行时切换误伤共享位。
- 旧档"纯视觉零碰撞变化"(v0.15)废除;编辑器契约 speed-dev
  docs/data-contract.md §2.1 lane 语义同步。

> v0.18 起被 §7.10 **分层语义 v3** 迭代:lane 拆为八层定值 `layer`
> (1–8)+ `who` 集合,本节谓词(`applies_to ∧ lane_for==mid`)将被替代。

## 7.10 分层语义 v3(v0.18.0 实装 · 2026-09-10 定稿)

> 七项逐项拍板(2026-09-10):① who 回归**集合值**(一座建筑物/机关可
> 对应多个几何体 id);② `lanes` / `far` 废弃,分层差异拆两个组件;
> ③ 八层**全局定值**,每关选用子集;④ 实体性写入层表,实体层按几何体
> id 校验实体化,组件另配**编号 id**(利好地图编辑器);⑤ 充电桩立项
> (双子踩住 → 磁界整体失效);⑥ 高亮/暗度三档方案;⑦ 关卡设计补全
> 仍锁定在全部功能验证完美之后(ROADMAP §7)。
>
> 业界同构验证(2026-09-10 联网调研):Godot layer/mask、Unity 碰撞
> 矩阵、UE Object/Trace 通道全部把"我在哪(身份)"与"我和谁交互
> (感知)"拆成正交两字段,无一将渲染层与碰撞域合成一个字段;UE 的
> "增删通道重置全项目赋值"教训支持八层一次定稿。本节把 v2(§7.9)
> 中 lane 身兼"渲染 + 碰撞域"两职的历史包袱彻底拆开。

### 八层定值表(全局固定,一次定稿)

| 层 | 定值语义 | 实体性 | z 基准 |
|---|---|---|---|
| L1 深景 | 纯视觉最暗档(原 far2) | 景观 | -2 |
| L2 远景 | 沉降档(原 far1) | 景观 | -1 |
| L3 背景建筑 | 可穿行装饰(原 back) | 景观 | 0 |
| L4 主实体层 | 全员共享地形(原 mid) | 实体 | 1 |
| L5 扩展实体层·甲 | 专属/分组实体域 | 实体 | 2 |
| L6 扩展实体层·乙 | 同上,不同深度 | 实体 | 3 |
| L7 扩展实体层·丙 | 同上,再高一层 | 实体 | 4 |
| L8 前景遮挡 | 玩家之上剪影(原 front) | 景观 | 6 |

- 八层的语义与 z 基准全局一次定稿;**每关只用其中子集,未用的层留空**
  ——数据里不出现的层不产生任何节点与碰撞位。
- **实体性写在层表里**:景观层(L1–L3 / L8)一律纯视觉、几何体自由
  穿行;实体层(L4–L7)的组件按 `who` 校验逐几何体实体化。数据不再
  逐组件决定"这层算不算实体"。
- L5–L7 是三条不同深度的**自由实体层**:同一层可承载多个不同 who
  集合的组件(如疾专属墙 who={0} 与逆专属墙 who={2} 同在 L5),
  靠 who 区分归属、靠层区分深度。z 与既有机关物(终点门 3 / 磁界 4)
  相邻,同值由场景树序稳定,实装时如穿插异常可微调机关 z。

### 组件语义 v3:双归属 + 编号

```
组件 = { id, 几何(位置/尺寸/折点), layer, faces, who, tags, … }
  id    = 组件编号            关内唯一,建议按层分段编号(L4 首件 = 401);
							  调试指向 / 高亮指向 / 存档 / 未来编辑器引用
  layer ∈ 1..8                第一归属:所在图层(上表),缺省 4
  faces ∈ full | top | bottom | none   保留(§7.3),只收窄碰撞面方向
  who   = 几何体定值 id 集合   第二归属:与哪些几何体交互;空 = 全员共享
  tags  = 保留
  (lanes / far 废弃)
```

- **who 是集合**(拍板①):`who={0,1}` = 疾跃共用;空 = 全员共享地形。
  几何体定值 id 沿用名册下标(疾0 跃1 逆2 圆3 伍4 含界边两半,
  陆5 柒6 预留),七几何体恰一字节,需要时可无损升级位掩码存储。
- **双子粒度**:who=4 时界/边两半同权;"仅某半体"的细分暂不做,
  真出现需求再加半体位(拍板⑤的前提件充电桩只需 who={4})。
- **组件编号 id**:每关内唯一,建议按层分段(L4 的第 3 件 = 403),
  供调试日志、高亮指向、存档与未来地图编辑器引用;缺省可省略
  (运行时自动分配负数临时号)。

### 实体化与碰撞规则

- **实体化谓词(唯一函数,渲染与碰撞共用)**:组件 C 对几何体 g 有
  碰撞 ⟺ `layer(C) ∈ L4..L7` 且(`who(C)` 空 或 `g ∈ who(C)`)且
  `faces(C) ≠ none`。v2 中 `_midset` 与 `_solid_for` 两份手写拷贝
  在此合并,消灭"看着实心却穿过去 / 看着虚化却被挡"的回归面。
- **碰撞位编译**:签名键从 midset 改为 `(layer, who 集合)`,构建期
  动态分配机制不变;**新增上限守卫**——组合位自 bit3 起分配、上限
  bit29(共 27 槽),bit30 起为磁界等特权位,超限构建期直接报错。
  修复 v2 隐患:签名涨满时组合位会撞上 `BOUNDARY_BIT(1<<30)`,
  届时逆/双子边界豁免与机关切位全部被磁界牵连。
- **置换(逆)落点**沿用 §7.5 语义过滤,谓词换用上式
  (该过滤至今未实装,随 v3 一并收口)。

### 高亮 / 暗度三档(拍板⑥)

受控几何体切换时,**全部组件含机关物**(修复 v2 只有 platforms 参与
虚化的缺口:机关物对多数几何体无碰撞却画成实心)按双归属算显示档:

| 档 | 条件 | 视觉 |
|---|---|---|
| 专属·亮 | who 非空且含受控者 | 该几何体专属色微提亮 + 描边脉冲 |
| 共享·常 | who 空 | 正常亮度 |
| 无关·暗 | who 非空且不含受控者 | 幽灵档(0.35;L8 前景 0.45) |

- 景观层组件不参与三档,走常驻景观 alpha 规则(渗雾 / 沉降)。
- 专属描边色 = **当前受控几何体色**(亮的是"属于他"的东西),
  不取 who 集合平均色;切换沿用现有波次交叉淡化,无跳层 pop。
- 高亮同时是可读性设计:Trine 系"角色专属机关"靠美术暗示,本方案
  由 `who` 字段系统性驱动,新机关零额外美术成本自动获得高亮。

### 磁界与充电桩(拍板⑤)

- 磁力边界现状不变:阻拦除逆(蓝)外的其他几何体;伍两半为磁力线
  端点、天然豁免(characters.md §5)。
- **充电桩 ChargingPile 立项**(structures.md §5,后续实装):
  who={4},伍任一半体踩住期间,磁感线边界特性**整体失效**——不再
  阻挡任何几何体;离开即恢复。归属字段只管"谁能触发",效果域
  (全局开关)属逻辑层——"触发归属 ≠ 效果范围"的范例件。
- 充电桩不新开字段:踩踏判定复用 LeverGate 的玩家层 Area2D 路线,
  唯一差异是效果目标从"自家门板"换成"MagBoundary 总开关"。

### 8.2 分区坐标系 zones(v0.20.0 实装)

关卡声明命名分区,网格从"均匀线阵"升级为"带行政区划的地图":

- 数据:`def.zones: [{rect, name, layer?}]`——rect 吸附整格;name
  关内唯一(如 "Z1 八层展区");layer 可选,分区标注渲染在该层网格
  (缺省随 L4)。与分层体系强关联:**分区也是组件,同样挂层**。
- 呈现:分区名以低亮度纸白标注在分区左上格点(近景 LOD 显示);
  HUD 坐标读数扩展为 `分区名 · x,y`(跨界防抖 0.5s,防进出闪跳)。
- 引用:tours / hints / 调试日志 / 存档可记分区名而非裸坐标——
  v3→v4 重设计时 laneshot 与 tours 节拍全部手工重标的教训:
  坐标引用失配是布局迭代的最大摩擦,分区名是稳定引用键。

### 8.4 吸附纪律与 --gridcheck(v0.20.0 实装)

- **吸附规范**(Tiled "Snap to Grid" 的数据版;纪律由校验器执行):
  全部数值为**整数像素**(硬性);对齐 0.1 格为建议级(落地缓冲类
  5px 悬停——出生点 / 门心 / 坡末端——允许并计 WARN)。
- **`--gridcheck`(headless 校验器)**:装载关卡数据逐项检查:
  1. 吸附违规(按上表);
  2. **净空检查**:faces=full/top 可站立顶面上方 1.0 格内不得有实体
	 (按 §7.10 谓词对 who 内每个几何体分别裁定);
  3. 行程检查:mover / 电梯扫掠体与实体相交(placement 纪律机器化);
  4. 越界检查:组件出关卡边界、侵入 kill 区;
  5. 伍门可达启发式:双体门 ±50 区内同时存在界(天花底)与
	 边(地/台)落点(防死局复发);
  6. **共面接缝检查**:实体竖直侧壁的底缘不得与可行走面齐平
	 (须嵌入承载面 ≥0.5 格)——高速贴地移动撞上零高度差接缝会
	 转角穿模卡死(v4 实测:疾冲刺嵌入气闸门板下缝)。
  违规输出 `GRIDCHECK FAIL: <id> <规则> <坐标>`,**退出码非零**,
  接入发版钩子。运行:`godot --headless --path . --script
  res://tests/grid_check.gd`(可加 `-- --level=N` 单关)。六类检查
  已全部实装,v4 试炼场为首个全绿关卡(12 条落地缓冲 WARN)。

### 8.5 渲染与 LOD(已实装,v0.13)

1. **三级 LOD**(密度随视距自适应):近景 = 次格 1 格细线 + 5 格
   主线;中景 = 仅 5 格主线;远景 = 10 格点阵 + 缘坐标数字。
2. **坐标数字**:上 / 左双缘刻度,远景档边缘显示。
3. **视差解耦**:背景装饰 scroll_scale 与网格不同频,无摩尔纹。

  红色左缘刻度),渐显半径 6.2 → 7.8 格,触屏字号 15 → 17——
  真机户外可读性优先。
- **首摔安抚**:序章内首次死亡时旁白"摔碎不是终结 · 空白处会把你
  重新拼好"(序幕规则拍的玩法回响,每次启动至多一次)。
- **文案打磨**:全部提示语统一"动作在前、原理在后"的短句式;
  触屏变体逐条核对(float 轮盘"右半屏点按"替换词全覆盖)。
- 序章各关开场卡(`intro`)与关卡内提示牌分工:开场卡讲本关概念,
  提示牌只讲脚下这一步,不重复。
